# PCAP Report JSON / Output Schema Evidence

Evidence source: `Backend/pcap_engine/reporter.py` `build_report`, plus sample `Backend/pcap_runs/_jobs/.../report.json`.

## Top-Level Fields

| Field | Type | Meaning | Created in | Displayed in frontend | Safe to mention |
|---|---|---|---|---|---|
| `meta` | object | report generation and pipeline metadata | `build_report` | status/artifact/admin | Yes, but sanitize paths |
| `summary` | object | total flows, risk/security summaries | `build_report` | KPI cards, security score, admin | Yes |
| `module_contract` | object | dashboard module score/status contract | `_build_pcap_module_contract` | dashboard/monthly integration | Yes |
| `risk_per_ip` | array | per-IP risk rows | `_build_risk_per_ip` | `RiskPerIpCard` | Yes |
| `clusters` | array | grouped attack patterns | `cluster_alerts` | clusters table | Yes |
| `alerts` | array | flow-level promoted alerts | `build_report` | alerts drilldown | Yes |
| `timeline` | array | flow-level time series | `build_report` | timeline charts/selectors | Yes |

## `meta`

Fields:
- `generated_at`: ISO timestamp.
- `pcap_path`: source path. Sensitive; do not show raw real path.
- `run_folder`: string such as `tshark+cic` or `tshark+cic+zeek`.
- `zeek_requested`: boolean.
- `zeek_enrichment_succeeded`: boolean.
- `zeek_evidence_available`: boolean.
- `analysis_mode`: `enriched` or `base_only`.
- `comparison`: object with `compared_rows`, `changed_by_evidence_up`, `changed_by_evidence_down`, `base_only_rows`, `enriched_only_rows`.
- `pipeline`: repeats pipeline metadata.
- `artifact_protection`: may be added later by artifact protection hook.

## `summary`

Fields:
- `total_flows`: integer.
- `alerts_count`: integer.
- `suspicious`: integer.
- `malicious`: integer.
- `overall_risk`: float `0..1`.
- `risk_level`: string: `Normal`, `Low`, `Medium`, `High`, `Critical` depending logic.
- `risk_context_label`: string.
- `risk_display`: string.
- `top_attackers`: array of `{src_ip, count_flows}`.
- `security_score`: float `0..100`, higher is safer.
- `score_explanation`: object or null.
- `security_score_level`: string: `Secure`, `Warning`, `Risky`, `Critical`.
- `top_risk`: object or null.
- `security_summary`: string generated by code.
- `summary`: duplicate summary string.
- `security_trend`: string generated by code.
- `cluster_count`: integer.
- `severity_counts`: object `{low, medium, high, critical}`.

## `alerts`

Each alert object can include:
- `type`: `"ML"`.
- `ts`: numeric timestamp.
- `src_ip`, `dst_ip`, `dst_port`.
- `ml_label`.
- `ml_confidence`, `classification_confidence`.
- `confidence`, `threat_confidence`.
- `severity`.
- `reason`.
- Zeek/enrichment fields: `zeek_service`, `zeek_conn_state`, `zeek_proto`, `zeek_duration`, `zeek_bytes`, `dns_top_query`, `dns_query_count`, `http_top_host`, `http_top_uri`, `http_request_count`, `ssl_top_sni`, `ssl_event_count`.
- `heuristic`: `{type, score, reason}`.

Safe to mention: yes, but note HTTP URI/DNS/SNI may be sensitive.

## `clusters`

Each cluster object includes:
- `attack_type`
- `src_ip`
- `dst_ip`
- `count_flows`
- `top_dst_ports`: list of `{port, count}`
- `top_dst_ips`: list of `{ip, count}`
- `max_confidence`
- `max_threat_confidence`
- `max_ml_confidence`
- `severity`

## `risk_per_ip`

Each row includes:
- `ip`
- `role`: `source`, `destination`, or `both`
- `threat_count`
- `suspicious_count`
- `top_severity`
- `max_confidence`
- `ip_risk_score`
- `top_attack`

## `timeline`

Each row includes:
- `ts`
- `src_ip`
- `dst_ip`
- `dst_port`
- `ml_label`
- `ml_confidence`
- `classification_confidence`
- `confidence`
- `threat_confidence`
- `verdict`

## Export Fields

Export endpoints do not add schema fields; they send:
- `report.json` as JSON.
- Evidence ZIP containing report/state and Zeek logs when available.

Evidence:
- `Backend/app.py` `export_job_artifact`, `_build_job_evidence_bundle`.
